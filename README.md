# Cross-dataset motor-imagery EEG: loss decomposition and scale-consistent covariance alignment

Code for the analyses of cross-subject and cross-dataset motor-imagery (MI) EEG decoding:
decomposition of cross-dataset performance loss, a numerical scale-equivariance check of
covariance-whitening alignment (Euclidean Alignment, EA), the incremental value of dataset-level
alignment, and target-data access conditions, with a pre-specified confirmation on Dreyer2023 and a
sealed validation on Stieger2021.

Data are not included. Results are not included; they are regenerated by the scripts below.

## Euclidean Alignment and numerical regularization

`eeg_ea.euclidean_align` whitens each subject with the inverse square root of its mean trial
covariance. Exact whitening is scale-equivariant: multiplying the EEG by a positive constant must not
change the aligned data. The regularization of small eigenvalues is selected with `eps_mode` or the
environment variable `MI_EA_FLOOR`:

| Mode | Eigenvalue handling | Scale-equivariant |
|---|---|---|
| `relative` (default) | float64, floor `1e-8 * trace(R) / C` | yes |
| `rank_aware` | truncated inverse below `1e-12 * max eigenvalue` | yes |
| `absolute64` | float64, absolute floor `1e-8` | no |
| `legacy` | float32, absolute floor `1e-8` (original implementation) | no |

MNE and MOABB return EEG in volts, so the reference eigenvalues of several datasets fall below an
absolute floor of `1e-8`. The absolute modes are kept only to reproduce the comparison conditions.

## Scale-equivariance checks

```bash
python tools/check_scale_equivariance.py --synthetic            # volt-scaled synthetic data
python tools/check_scale_equivariance.py --npz path/to/data.npz # keys X, subjects
```

For each mode the tool reports: the change of the aligned data under rescaling (x1e-6 to x1e6);
whether each subject's aligned covariance is proportional to the identity; the numerical rank of the
reference covariances and the number of eigenvalues below `1e-8`; and alignment-order equivalence
(subject EA followed by dataset EA should change nothing; dataset EA followed by subject EA should differ
from subject EA only by an orthogonal matrix per subject). The exit code is 1 if the default mode fails.

## Data preparation

All inputs use left- vs right-hand imagery, 8-30 Hz, 0.5-2.5 s after the cue, 100 Hz, stored in volts,
without ICA. Place the files as listed in `data_manifest/SHA256SUMS`.

| Dataset | Script | Notes |
|---|---|---|
| Cho2017, Lee2019 | `MI_test/MI_loso_project/preprocess_moabb_sfreq100.py` | MOABB `MotorImagery` path, 201 samples; Lee2019 training phase of both sessions |
| BNCI2014-001 | `analysis_outputs/cmpb_bdea_20260924/prep_bnci2014001.py` | keeps session and run labels in chronological order |
| PhysionetMI | `analysis_outputs/cmpb_bdea_20260924/prep_physionetmi.py` | keeps run labels in chronological order |
| Dreyer2023 | `analysis_outputs/cmpb_confirmation_dreyer2023/prep_dreyer2023.py` | data-preparation environment |
| Stieger2021 S21-S62, session 1 | `analysis_outputs/cmpb_method_A_budget_fusion/download_stieger_session1.py`, then `prep_stieger2021.py` | downloads only session-1 files (MD5-checked). ## Pre-specified analyses

- **Dreyer2023 confirmation.** Hypotheses H1-H6, tests and decision rules are fixed in
  `analysis_outputs/cmpb_confirmation_dreyer2023/CONFIRMATORY_PLAN.md`, written before the data were
  downloaded. Run `prep_dreyer2023.py` (data-preparation environment), then `run_confirmatory.py` and
  `analyze_confirmatory.py`.
- **Few-shot fusion rule with a sealed test.** `analysis_outputs/cmpb_method_A_budget_fusion/DESIGN.md`
  (with dated amendments) defines the candidates, the selection rule and hypotheses A1-A3. `run_dev.py`
  and `analyze_dev.py` select and freeze the rule in `FROZEN.json`; `run_sealed.py` runs the single test
  on Stieger2021 and refuses to run if `DESIGN.md`, `run_dev.py` or `analyze_dev.py` differ from the hashes
  recorded at freezing.

Both plans were fixed and time-stamped before the corresponding data were accessed; they were not
registered in a public registry.

## Relation to earlier code

Results produced with the original absolute-floor EA are superseded. In this release the EA default
is `relative` (earlier code defaulted to `legacy`), wrapper functions no longer force `legacy`, and
`cross_dataset.run_cross(seed=...)` sets the training seed. The analyses above select the EA mode
explicitly, so these default changes do not alter their results.
